# bgmkit — BGM動画の制作パイプライン

Whispers of Japan の Vol.5〜10 で巻ごとに書き捨てていた44本のスクリプトを、
**1つのパイプライン + 設定ファイル2層**にまとめたもの。

新しいジャンルを立ち上げるときは `genres/` にYAMLを1枚足すだけで済む。

```
genres/<ジャンル>.yaml   音の設計・映像の作り・サムネの型（巻をまたいで固定）
volumes/<巻>.yaml        素材の場所・タイトル・場面・曲順（巻ごとに変わる）
```

巻の側に同じキーを書けばジャンルの値を上書きできる。

## 使い方

```bash
cd /Users/ryo/youtube/bgm
python3 -m bgmkit analyze vol11    # 候補曲を計測して重複を検出
python3 -m bgmkit select  vol11 --write
python3 -m bgmkit order   vol11 --write
python3 -m bgmkit build   vol11    # 音声→映像→書き出し→サムネ を通しで
```

`--write` を付けると結果が `volumes/vol11.yaml` に書き戻される。
個別に回したいときは `audio` / `video` / `mux` / `thumb` を単体で呼べる。

中間生成物は素材フォルダの `_work/` に置かれる。
（一時領域には置かない。Vol.10 ではセッション終了で manifest が消えて作り直した）

## 巻のYAMLに書くこと

```yaml
genre: whispers
volume: 11
dir: "~/Desktop/Whispers of Japan/Vol11_素材_xxx"
background: "~/Desktop/Whispers of Japan/Vol11_背景_01.png"
title_lines: [MOONLIT, SOMETHING]
runtime: "27 MIN"

kinds:                    # ファイル名（" (1)" を除く）→ 音色の種類
  Koto in the Mist: ①箏独奏
  ...

select:
  kind_limits: {⑥フル編成: [1, 1]}
  breath_floor: {②尺八: 0.05}

order:
  fixed: {1: ②尺八, 3: ③ピアノ独奏, 9: ⑥フル編成}

scenes: [...]             # 10個
images: [...]             # 10枚
```

## 各コマンドが守っている決めごと

すべて Vol.3〜10 の実測から出たもの。数値を勘で動かさないこと。

**analyze** — キー・ラウドネス・息の量・明るさ・全ペアの一致度を測り `_work/analysis.json` に落とす。
- 一致度は**メルスペクトログラム系列のスライディング相関**。平均クロマは全曲ドローン支配で
  0.93〜0.99 に張り付き使えない。0.5以上=同一生成の別テイク / 0.2以下=別の曲。
- 息の量は**パワースペクトル**の1-5kHz平坦度。振幅のままだと6倍大きく出て目安が狂う。
- デコード後MD5で完全同一を検出する。ファイル名では判別できない。

**select** — 全探索で本採用を選ぶ。
- `max_per_kind` が要。一致度の最小化だけだと音数の少ない独奏が指標上有利になり、
  Vol.9では10本中4本がピアノ独奏になった。
- `breath_floor` で息の足りない笛を先に切る。後から一致度で選ぶと純音に近い個体が勝つ。

**order** — 分枝限定で隣接一致度を最小化する。
- 「2つ飛びも同じ種類にしない」を入れる。隣接だけ禁じると A-B-A-B が通る。
- **明るさの起伏を条件に入れない。** 種類を分けた設計そのものが31dBの差を生むので、
  揃えようとすると一致度が悪化し、同じ種類が前半に固まる。

**audio** — 頭尾の無音をトリム → loudnorm 2パスで -14 LUFS に統一 → クロスフェードで連結。
- Sunoの生成物は曲ごとに -13〜-16 LUFS と3LUほど開く。統一しないと曲が変わるたび音量が動く。

**video** — ケンバーンズ + クロスフェード + エンドカード。
- ケンバーンズに `zoompan` を使わない。整数ピクセルでしか動けず、遅い動きだと
  4秒に1回1〜2pxカクッと飛ぶ。`perspective` なら 0.001〜0.010px に収まる。
- 画像の尺を等分しない。曲の変わり目に映像の切替の中心を合わせる。
  等分するとVol.6では最大32秒ずれた。
- エンドカードは本編の後ろに足さない。最後の場面からクロスフェードで入り、
  カードの上で音楽を消す。

**thumb** — 168px（PCの関連動画欄）で読めることが唯一の基準。
- `.ttc` のフォント番号は役割ごとに違う。まとめて指定すると尺バッジとタグラインだけ字面が変わる。
- タグラインに SLEEP や環境音系の語を入れない。実体と違う語は期待外れの離脱を招く。

## 旧スクリプトとの対応

| 旧（巻ごとにコピー） | 新 |
|---|---|
| `analyze_tracks_vol*.py` + `check_duplicates_vol*.py` | `analyze` |
| `select_vol*.py` | `select` |
| `order_vol*.py` | `order` |
| `prep_audio*.py` | `audio` |
| `build_vol*.py` | `video` |
| （毎回手打ちしていた afade + AAC 書き出し） | `mux` |
| `make_thumbnail_vol*.py` | `thumb` |

旧版はスクリプトが `print` した表を正規表現で読み直していて、書式を変えると壊れた。
新版は `analysis.json` を介して受け渡す。

## Vol.10 での検証

旧スクリプトと同じ素材で回して確認した。

- 選抜10本 … **完全一致**
- 曲順 … 隣接の最大 0.348 で旧と同じ、平均は 0.297→0.292 とわずかに改善
  （場面6と7が入れ替わる。どちらも制約を満たす同値の解）
- 音声の長さ … **1574.36s**。旧 `build_vol10.py` の `T = 1574.356` と一致
- サムネイル … **1画素も違わない**

なお旧 `order_vol*.py` の `adjacency_threshold: 0.28` は、実際に公開したVol.10の曲順
（最大0.348）を弾く値だった。探索自体が最大値を最小化するので足切りは既定で無効にしてある。
