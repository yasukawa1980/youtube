### 元素材の照合と再利用方法

8ショート候補の完成MP4、専用台本、元音声、縦画面素材を実在確認。アヌビス・スフィンクス本編の完成英語MP4とタイムラインも確認。パスと検査結果はJSONの各候補に保存した。アヌビス/H3はv02完成品がv01の音声・素材記録を参照し、M1/M3/P1も旧版ディレクトリの音声・素材を利用する。**最新版フォルダだけコピーしても再現できない**ので、参照先を含む依存関係が必要である。

A1/H3、M1/M3、P1、S1/S2/S3を含む4制作セットの `visual_manifest.json` から33ショットの参照画像パスを検査し、33件とも実在した。ここで確認したのは編集に使用した画像パスであり、全作品の原寸素材・権利・ハッシュの再監査ではない。

完成MP4を繰り返し加工するより、既存の元画像・音声ステム・字幕時刻から新版を描画する。文章不変の音声は再利用できるが、順序変更で息継ぎや文脈が不自然になる場合は短いショート音声全体を同じ声で再生成し、字幕とカットを同期する。既存ファイルは保持し、別バージョンへ出力する。

## 4. 賛成できる提案と、そのまま採用しない点

### 賛成

- 冒頭を最優先にする。A1は結論が約14秒以降にあり、制作記録と離脱仮説が整合する。ただし相関であって原因確定ではない。
- 1本の本編から3ショートを基本にし、新規獲得・知識発見・本編誘導の役割を付ける。どの役割でも短い答えを完結させ、関連動画へ進む価値を具体化する。
- 削除せず、版と実質的な変更点を残す。新規生成より既存の権利確認済み素材とローカル音声を優先する。
- エジプトを検証枠に含める。ただしP1・M3も対照に残し、伸びたショートと本編の成績を別々に見る。

### 問題点・懸念

1. **新しい冒頭カードを1〜2秒付け足すだけでは、説明の開始を遅らせる。** 最初のフレームから絵・短い見出し・語りを同時に開始し、導入の置き換えを基本にする。既存S2/S3に二重の導入は加えない。
2. 提案例の `Anubis Didn't Judge the Dead. So Who Did?` は否定が強すぎる。既存題は末尾に **Alone** がある。審判への関与まで否定せず、「一人ではない」を保持する。Metの資料はアヌビスの計量、トトの記録、オシリスや審判団の役割を記述する。[Metの当該資料](https://www.metmuseum.org/art/collection/search/557657)
3. 5本対5本で題材・公開時期・尺・CTA・音声・画角を一度に変えると原因を分けられない。過去5本と将来5本だけでは配信相手やチャンネル成長も交絡する。
4. 「平均再生率が高い」は全視聴者の完走を意味しない。S2の196.9%も継続視聴・反復の性質を含む指標で、倍の人数が完走したという意味ではない。
5. 50/30/20を本編とショート双方へ機械的に課すと、3本派生の関係と競合し、不要な再制作が増える。まず本編企画の分類として試す。ショートは別にA/D、新規台本、役割、使用元を記録する。
6. チャンネルは10/21開設。本編の再生数が小さく、リピーターや登録率の安定判定には早い。公式のコア視聴者は6か月超の継続を含むため、14日試験の成功指標にはしない。[視聴者の公式定義](https://support.google.com/youtube/answer/12220281?hl=en)

### 代替案

- **「全部を再投稿」ではなく、「全作品を診断対象にする」**。入口が弱ければ題・サムネや冒頭、本文も弱ければ構成、好調なら新しい問いへの展開を選ぶ。
- 最初はA1とM1を冒頭改善の試作候補にし、S2/S3は成功例として維持。H3は季節待ち。新規題材を止めず、P1・M3の構成も新作へ反映する。
- 次の10本編案はエジプト・古代文明4枠を上限目安にし、2本ずつ反応を見て残りを決める。地理的な題材分類と「新規／過去題材／再制作」は別軸で記録する。
- 50/30/20は「新規5、別角度3、再制作は最大2」の候補枠とする。全編再制作の根拠がなければ2枠は新規・別角度へ戻す。投稿枠を埋めるために作らない。
- ショート①は具体物＋意外な結論、②は一つの資料が示す証拠、③は答えを一つ渡した上で本編の残る問いへ。登録依頼と本編誘導を常に同じ強さで並べる必要はなく、EP009の結果を見て一つの主要行動に絞る案を検証する。

| 役割別の場面選定・英語案 | 規則で候補を絞り、必要時だけ言語モデルで案を出す | 候補案から承認済み台本へ直接上書きしない |
| 予約投稿・関連動画 | 現行Studio方式を維持。候補の提示、承認、投稿、本編公開確認、関連付け、再表示検証 | UI変更・Mac起動・認証・チャンネル違いに弱い。失敗時は停止・記録 |

### APIと本編への誘導

関連動画はStudioで追加でき、上級者向け機能へのアクセスと公開/限定公開の接続先が必要。予約のために本編を限定公開へ変えることは提案しない。[公式手順](https://support.google.com/youtube/answer/14075157?hl=en)

確認した公開Data APIのvideoリソースには、Shortsの関連動画を設定する文書化されたフィールドが見当たらない。**公式APIで自動設定できると約束せず、既存のStudio操作を継続**する。これは公開仕様の調査からの判断であり、非公開APIは使わない。[videoリソース仕様](https://developers.google.com/youtube/data/reference/rest/v3/videos)

Analytics APIは動画別の視聴、平均時間/割合、登録増減などを取得できるが、レポートごとに指標・ディメンションの組み合わせ制限がある。視聴継続率、フィード機会、関連動画リンクの直接クリックをすべて同じAPIで取得できる前提にしない。日付境界もJST予約表と別に保存する。[指標一覧](https://developers.google.com/youtube/analytics/metrics)・[チャンネルレポート](https://developers.google.com/youtube/analytics/channel_reports)

本編流入の「関連動画16.4%」はShorts内の関連動画ボタンのクリック率ではない。流入元のShorts等の分類が表示されればその視聴数・時間を保存するが、発生元ショートIDまで分からなければ帰属は未確定とする。動画別の登録増加数も、ショート→本編→登録という個人単位の経路を証明しない。直接流入が取れない場合は、本編側の該当期間の視聴時間・流入分類・形式間の視聴者重複を補助指標として使う。

### 台帳の案

`channel_id + youtube_video_id`を公開動画のキーにし、制作物は`episode_id + short_id + version`で管理。候補段階は動画IDをnullにする。`short_id`のT1は天狗とトロイの両方にあるため、単独キーにしない。

保存する項目：形式、公開/予約/旧版、初回公開・再予約時刻、親本編ID、関連動画の確認日時と接続先、題材、3本の役割、台本・出典・権利・素材・音声・完成品・ハッシュ・旧版依存先、処理時間、費用/クレジット、テスト群、変更内容。指標は別テーブルにして、取得日時、期間開始/終了、タイムゾーン、公開後経過、取得元、分母、未取得理由を付ける。

初期の候補規則は、同じ形式/尺/公開後日数で比較可能かを先に判定し、①低継続・高再生率、②登録/反応、③素材再利用可能性、④季節、⑤修正負担で分類する。欠測を0点にせず「判定保留」へ。細かな重み付き点数で精度があるように見せるより、理由付きの優先度を出す。

### 費用・時間・保存容量

- **今回の生成API呼出し・Kling消費・新規購入は0。** 承認後も既存素材＋ローカルKokoro＋FFmpegのみなら、生成APIの追加従量費やKling消費を発生させずに試作できる。電力・既存契約・助手利用枠・人の作業時間は別。
- クラウドLLMでの候補生成を後で導入する場合は、入力/出力トークンと実際のモデル料金を記録。現在の契約枠や外部画像生成の最新単価は未調査なので金額を推定しない。新規AI映像を必須にしない。
- **処理時間は今回未測定。計画用の仮見積もり**：既存素材のショート1本につき構成・史料・英語確認15〜45分、ローカル音声/レンダー/技術QA 5〜20分、最終試聴・画面確認5〜15分。初回試作で壁時計時間と人の作業時間を別々に測り、この幅を更新する。全編再制作は初回試作後に見積もる。
- **開発の仮見積もり**：台帳の読み取り・既存記録取り込み0.5〜1.5作業日、役割/版パラメータの共通化1〜3日、API認証を含む継続取得2〜5日。既存コードを一括置換せず段階追加する。合算で確約する納期ではない。
- **容量実測**：S1/S2/S3の公開v03完成MP4は合計19,501,720 bytes（約19.5 MB）。M1〜M3 v02は15,816,633 bytes（約15.8 MB）。アヌビス本編英語v09は183,154,458 bytes、スフィンクス本編英語v02は150,173,048 bytes。
- Sphinx v03フォルダは比較用旧版も含むdeliverables約62.1 MB、音声約6.6 MB、画像約8.9 MB、`_work`約7.4 MB。最終MP4だけの容量と制作一式を区別する。10ショートの完成品を既存実測から外挿すると約53〜65 MBだが、再現用キャッシュ・旧版込みの上限ではない。容量不足を防ぐため、本人指定のESD-02を利用する案とし、今回は移動・削除しない。

## 6. 優先順位を付けた14〜30日の実行計画

**Day 0は運営者の承認日。11/2から制作を開始済みという意味ではない。既存の11/2〜7予約・依頼を変更しない。** 次の公開枠を使う際はライブ一覧で再照合する。

| 優先度・期間 | 承認後の行動 | 判断基準・成果 |
|---|---|---|
| P0・Day 0〜3 | 台帳の最小版、既存版・関連動画の照合、同一期間の基準値保存。EP009のCTA試行を区別 | チャンネルID一致、動画ID重複/旧版区別、未取得項目の明示。公開・予約の自動変更なし |
| P1・Day 1〜7 | A1/M1の改善案と短い試作を提示。S2/S3の72時間/7日を観察 | 短い見出しと最初の語りが一致、史料限定、冒頭から答えに向かう。試作の技術/試聴合格後に公開候補を承認 |
| P1・Day 4〜14 | 今後の自然な制作枠で5組程度を比較。現行承認済み方式5本と、改善対象を一つに絞った方式5本 | 同系統題材・役割・尺帯・声・時刻帯をそろえ、群の割り当てを事前記録。公開後72時間/7日で比較 |
| P2・Day 14〜21 | 最終公開分にも7日を確保して中間評価。本編流入と制作負荷を併記 | 継続だけ上がり視聴時間が大幅に下がる案は再検討。登録・本編視聴が少なければ結論保留 |
| P2・Day 21〜30 | データ不足なら延長。再現した要素だけ共通化し、次の10本編の題材配分を調整 | 新しい題材・別角度を中心に、全編再制作は必要性が確認された作品のみ |

10ショートは3本セットの倍数ではない。4本編×3ショートの12本が通常工程で生じるなら、そのうち役割・題材が対応する10本を比較対象、残り2本を観察対象とする。12本を14日で作ることは要求しない。枠が足りなければ検証期間を延ばす。旧作品の再編集と新規作品を混ぜた比較も、作品履歴の影響を記録する。

主指標は視聴継続率。全体25〜30%は内部の方向目標として残すが、S2がすでに51.6%なので、各作品・組ごとの差を中心に評価する。候補の採用目安は「5組中4組程度で同方向、群の中央値で+5ポイント程度、平均視聴時間に大きな悪化なし」と仮置きし、統計的有意差を保証する閾値とは呼ばない。

観察量の目安は各動画でフィード機会500件程度、EV100件程度。分母が未取得・未達なら達成済みとしない。少標本の登録は件数を優先し、必要なら同じ期間のEV1,000回当たり登録増を補助指標にする（視聴者の転換率とは呼ばない）。母数を取得できる場合のみ不確実性区間を付け、動画単位のばらつきも見る。自動で有意差を出すために閲覧回数を独立した人数と仮定しない。

CTA、題材、冒頭は別の試行として扱う。EP009の「登録案内＋固定コメント」とEP007/008を比較しても題材差があるため、効果を確定せず次作で再検証する。安易に従来の5.4%というチャンネル全体の値とS1一本を比べて成功判定しない。

投稿は**Quiet Origins単独で日本時間1日合計3本まで、ショート最大2本**。本編2本の日はショート1本、本編3本の日は0本。既存本編の日時は動かさず、追加実験のために上限を埋めない。

## 7. 既存システムへの変更案とリスク

最初の実装は「読む→候補と欠測を出す」だけに限定する。既存制作runnerは入口を維持し、新しいrole・variant・source_segment_ids等を任意設定として追加する。設定がなければ従来と同じ動作にする。出力は別バージョン、旧版は保持。投稿処理とは分離し、デフォルトで投稿・予約を実行しない。

リスクは①旧版依存先の欠落、②T1等のID衝突、③予約非公開の本編へ関連付けできない、④画面変更・認証・別チャンネル、⑤指標の窓/分母の混同、⑥話別コードの挙動差、⑦新旧再投稿による比較の交絡。対策は依存台帳・複合キー・公開確認・保存後再表示・取得条件保存・一話での試行・変更履歴とする。

再制作ではクロップや冒頭2秒の変更だけを「十分な新規性」と判定しない。新しい問い、追加の根拠、説明順や資料比較など、視聴者に増える価値を変更票で示す。AI・自動化自体が一律禁止という意味ではないが、反復的な大量生成と、独自解説の乏しい再利用は別途評価される。[収益化ポリシー](https://support.google.com/youtube/answer/1311392?hl=en)・[スパムポリシー](https://support.google.com/youtube/answer/2801973?hl=en)

Claudeに確認してほしいのは、A1の否定表現の強さ、M1の原典限定、S1の情報負荷、P1/M3からの新しい切り口、S2から女性王の王権表現へ展開する際の根拠、A/Dで未使用扱いにする場面の既存ショートとの重複である。スフィンクスの年代論など新しい専門テーマは、主流の研究と異説の位置付けを一次研究で確認してから採否を決める。

## 8. Claudeの11月2日提案との照合

冒頭は導入済み、A1が旧型、エジプトと型の効果を分ける、3本とも答えを出す、全編再制作を急がない、現行Studio方式を残す、という点は一致した。Claudeの「見える証拠・単体で分かる・確かさ」の候補選定基準と、文単位の史料/学説/伝承のラベル案は台帳の設計に採用を勧める。

| 論点 | Codexの補足・修正案 |
|---|---|
| 旧型15本を新型で順次作り直す | まずA1/M1の少数試作。P1は今回2人獲得・継続36.4%、T1はEV9のみ。旧型という理由だけで全面再制作しない |
| 題材をそろえるには同じ旧作の再編集しかない | 同題材の別の問い・同じ本編内の対になるショートでも条件を近づけられる。同じ動画の前後比較にも時期・配信先・再投稿の交絡が残る。どちらも厳密な無作為A/Bではない |
| 新型12本のデータがすでにある | 制作済みと公開・観測済みは別。EP007〜009の多くはこれから公開。将来の指標を現在の比較に入れない |
| エジプト3本/10本か4〜5本か | **まず3本を基本、4本目を追加検証枠**にする案が妥当。P1/M3の登録獲得もあるため、5本を先に固定しない |
| M1の見出し `MEDUSA WASN'T BORN A MONSTER?` | 問いにしても誤解を防げるとは限らない。既存台本のヘシオドスでは生来のゴルゴンという説明と逆方向に受け取られうる。`BORN A GORGON` 等と原典限定の語りで再検討 |
| A3の `WHY A JACKAL'S HEAD?` | 音声だけイヌ科と限定しても見出しの断定は残る。見出しと語りを一致させ、canine等を含めて史料に沿って決める |
| 日本42.0%、字幕なし97.4% | 10/27の全形式集計。日本在住＝非英語話者ではなく、字幕なしでも焼き込み英語字幕は見える。今回の地域別データは未取得。言語変更の根拠にしない |
| 制作・分析の追加コスト「なし」 | 外部従量費0で可能な案には賛成。ただし助手利用枠、検品・試聴時間、電力・保存容量は別に記録。処理時間の実測は制作承認後 |
| 改善しなければ40〜55秒に延長 | 尺の延長を自動的な次手にしない。離脱位置・情報負荷・語りと画面の整合を先に確認し、その後に尺だけを別試行する |
| 本編冒頭60秒にショートの問いを回収 | 今後の本編設計では有効。公開済み本編を無断で再制作せず、既存本編へ誘導するショートは現在の本編にある答え・章に合わせる |

Claude案の「心臓の計量」「夢の碑文」「天狗と山伏」は、新しい切り口の企画候補として残す。これは公開済み動画10本の監査とは別枠で、原典・未使用素材・新規性の確認前に制作へ進めない。クランプスの季節公開時期と11月前半の在庫確保も別に計画し、新作を不必要に止めない。
