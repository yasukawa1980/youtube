# Codexへの依頼：Mac内蔵ディスクとSSDの容量整理（2026-10-22 Claude作成）

本人の依頼：「SSD、内蔵共に不要なものを削除して動作を軽くしたい」。

`AGENTS.md` の「フォルダ整理」の決まり（動かす前に一覧を作って本人に確認、削除せず `_整理待ち/` への移動案にする）に従い、**2段階**で進める。本人が今回「削除したい」と明言しているので、第2段階では本人が承認した項目に限って削除してよい。

## 第1段階：調査と候補一覧（この段階では何も消さない・動かさない）

1. 現在の空き容量を記録する。対象：内蔵ディスク（`/`）と、接続されているSSD（`ESD-EPB`、`ESD-02` など。接続されていないものは「未接続」と記録し、別名のSSDを同じものとして扱わない）。
2. 容量の大きいフォルダを洗い出す（目安：1GB以上）。主な場所：
   - `/Users/ryo/Desktop/BGM/`、`/Users/ryo/Desktop/新チャンネル/`、`/Users/ryo/youtube/`
   - `~/Downloads/`、`~/Movies/`、`~/Library/Caches/`
   - 一時領域（`/private/tmp/` の音声ランタイムなど）、各プロジェクトの `_work/`・レンダーの中間ファイル・キャッシュ
   - Python・Homebrew・npm などのキャッシュ（`pip cache`、`brew cleanup -n` の結果など。**実行はしない**、量だけ確認）
   - ゴミ箱
3. 候補一覧を `申し送り/ストレージ整理候補_<日付>.md` に作る。項目ごとに次を書く：
   - 場所、サイズ、最終更新日、何のファイルか
   - 区分：**A 消してよい見込み**／**B 本人の判断が必要**／**C 残す**
   - 理由（例：「完成版MP4から再生成できる中間ファイル」「GitHubのDraft Releaseに同じものがありハッシュ一致」「Macにのみある原本」）
   - 消した場合に作り直せるか、作り直しにかかる手間
4. 区分の目安：
   - **A の候補**：レンダーの中間ファイル・区間映像のキャッシュ（`_work/`、`render/` の途中物）で、完成版が別に保存されているもの。同じ内容の重複コピー（SHA-256で一致を確認したもの）。アプリ・ツールのキャッシュ。ゴミ箱。不要になったダウンロードのインストーラ。
   - **B の候補**：古い版の完成動画（例：アヌビスのv01〜v08、ハロウィンのv01）。ただし **最新版・公開済みの元ファイル・本人が承認した版は残す**。古い版は「GitHubのDraft Releaseに確認用コピーがあるか」を併記する。
   - **C（必ず残す）**：公開済み・予約済み動画の元ファイルと素材、各チャンネルの最新完成版、Suno・DistroKid関係の原盤と音源、AI画像の原寸（生成に使ったもの）、美術館・図書館から取得した原寸素材、音声モデル（`_共通/音声モデル/`）、`~/.config/bgmkit/env` などの設定、Gitのリポジトリ（未送信のコミットを含む）、ESD-02 に保存した童謡単曲のコピー。
5. 一覧の最後に、A・B・Cそれぞれの合計サイズと、Aを消した場合・A＋Bを消した場合に空く容量の見込みを書く。
6. `bgm/production` にコミット・pushし、本人に確認を求めて止まる。

## 第2段階：本人が承認した項目だけ削除

- 本人が一覧で承認した項目だけを削除する。承認のない項目には触れない。
- 迷う項目は削除せず `_整理待ち/` に移す（同じディスク内で移動）。
- 削除の前に、Aの「重複」項目は残す側のファイルが存在しハッシュが一致することを再確認する。
- キャッシュの削除はツールの正式なコマンド（`pip cache purge`、`brew cleanup` など）を使う。システムのファイル（`/System`、`/Library` の中身）は触らない。
- 終わったら、空き容量を第1段階の値と並べて記録し、削除・移動した一覧と合わせて `申し送り/ストレージ整理結果_<日付>.md` に保存してpushする。
- 移動したファイルを参照しているyaml・mdがあれば、参照先を更新する。

## してはいけないこと

- 本人の承認がない削除。
- 公開済み・予約済み動画の元ファイル、原盤、原寸素材、音声モデル、設定、Gitリポジトリの削除。
- SSDの初期化・パーティションの変更。
- GitHubのDraft Releaseの削除（必要なら別途相談）。
